# The brief

Describe the board you want: what it is for, what it must do and what it must
not do. A brief drafted in a copperhead conversation replaces this file when
the project is built, and a hosted `create` run replaces it with the brief it
was given. Either way the sections below are where a refined brief ends up.

## Purpose

One or two sentences: what the board does and for whom.

## Parts

Parts by designator or part number where you care, by function where you do
not.

## Power

What comes in (source, voltage range, current available), which rails come
out and how much current each one carries.

## Interfaces

Every connector and bus, and what is on the other end of it.

## Physical

Board size and outline, mounting holes, layer count, assembly method,
enclosure and operating environment.

## Must not

What the board must never do, and limits it must stay inside.

## Open questions

Each question, and what it blocks until it is answered.

## Assumptions

Each thing assumed without the person saying so, and what changes if it is
wrong.
